# OneCode Coding Agent - 基础对话功能 Spec

## 背景
OneCode 是一个从零开始构建的命令行 AI 助手（Coding Agent），类似 Claude Code。本阶段是项目的第一步，目标是搭建基础架构并实现纯对话功能，为后续的 Agent 能力（工具调用、文件操作、代码编辑）打下基础。

## 目标
- 用户在终端启动 OneCode 后，看到小柴犬 ASCII art + 文字 logo 的欢迎界面
- 进入全屏交互式对话界面（TUI），包含独立的输入区、输出区、状态栏
- 用户输入问题后，OneCode 调用大模型 API，以 SSE 流式方式逐字打印回复
- 回复流式输出结束后，以 Markdown 形式美化展示（代码块高亮、列表缩进等）
- 对 API 调用失败有可恢复的错误反馈，不中断会话，用户可继续提问
- 支持多轮对话，AI 能记住之前说过的话（会话内记忆，不持久化）
- 支持 Anthropic Claude 和 OpenAI 两种 API 后端，通过配置文件切换
- 支持 Claude 的 extended thinking 功能（默认隐藏，可展开查看）

## 功能需求

### F1: TUI 界面布局
- F1.1: 启动横幅：ASCII art 风格的柴犬图案 + "OneCode" 文字 logo + 版本号 + 当前工作目录
- F1.2: 就绪提示行：显示一行就绪信息（如 "Ready to help. Type your message below."）
- F1.3: 对话区：按时间顺序展示历次用户输入与助手回复，用户消息和 AI 回复用不同样式区分
- F1.4: 输入框：底部带边框的输入框，含 ❯ 提示符与占位文字 "Send a message..."，支持多行输入
- F1.5: 状态栏：左侧显示活动 Provider 名称，右侧显示模型名称
- F1.6: 支持 Ctrl+C 退出程序

### F2: Provider 选择
- F2.1: 若配置文件中仅有一个 Provider，直接采用它进入对话
- F2.2: 若配置文件中有多个 Provider，启动后先呈现选择界面（方向键列表，列出各 Provider 的名称与模型）
- F2.3: 用户选定后进入对话界面，被选定者即本次会话的活动 Provider
- F2.4: 选择界面支持上下方向键导航，Enter 确认

### F3: 流式对话与 Markdown 渲染
- F3.1: 用户发送消息后，AI 回复以 SSE 流式方式逐字打印（实时呈现）
- F3.2: 流式输出过程中，状态栏显示"输出中..."
- F3.3: 流式输出结束后，将回复内容以 Markdown 格式重新渲染：
  - 代码块语法高亮
  - 标题、列表、链接等正确显示
  - 表格对齐显示
- F3.4: 渲染完成后，光标回到输入区，状态恢复为"就绪"

### F4: 响应计时
- F4.1: 自请求发出（开始等待模型）即启动计时
- F4.2: 等待期间显示 "Imagining… (Xs)"，秒数随时间递增实时更新
- F4.3: 收到首个增量后继续计时
- F4.4: 本轮回复结束后，定型显示该轮总耗时（如 "Done. 12.3s"）

### F5: 多轮对话
- F5.1: 维护完整的对话历史（用户消息 + AI 回复）
- F5.2: 每次请求将内置系统提示词 + 当前完整对话历史发送给活动 Provider
- F5.3: 对话历史仅保留在内存中，退出程序后清空

### F6: Provider 抽象层
- F6.1: 定义统一的 Provider 接口，包含 Chat 方法（流式返回）
- F6.2: 实现 Anthropic Claude Provider（支持 SSE 流式输出 + extended thinking）
- F6.3: 实现 OpenAI Provider（支持 SSE 流式输出）
- F6.4: 通过配置文件选择使用哪个 Provider
- F6.5: 接口设计支持未来扩展其他后端

### F7: Claude Extended Thinking
- F7.1: 请求 Claude API 时按配置决定是否启用 extended thinking
- F7.2: thinking 内容默认隐藏，不显示在输出区
- F7.3: 用户可通过快捷键（如 Ctrl+E）展开/折叠 thinking 内容
- F7.4: thinking 内容用不同样式（如灰色斜体）与正式回复区分

### F8: 配置管理
- F8.1: 支持两级配置文件：
  - 用户级：`~/.onecode/config.yaml`
  - 项目级：`./onecode.yaml`（当前工作目录）
- F8.2: 项目级配置覆盖用户级配置
- F8.3: YAML 配置文件支持多个 Provider，每个 Provider 包含：
  - `protocol`: 决定使用哪家 API（anthropic/openai）
  - `model`: 指定模型名称
  - `base_url`: API 请求地址
  - `api_key`: 认证密钥
- F8.4: 启动时加载配置，配置无效时报错退出并提示

### F9: 错误处理
- F9.1: API 调用失败（网络错误、超时、认证失败等）时，在输出区显示可读的错误信息
- F9.2: 错误发生后不中断会话，用户可以继续输入新问题
- F9.3: 流式输出过程中断时，保留已输出的部分内容，显示错误提示
- F9.4: 配置文件格式错误或字段缺失时，给出明确的错误提示并退出

## 非功能需求

### N1: 界面不阻塞
- N1.1: 网络请求与界面渲染互不阻塞
- N1.2: 流式数据以异步方式驱动界面更新
- N1.3: 等待与流式期间界面始终保持响应（可滚动、可见进行中指示），不得冻结

### N2: 流式实时性与等待反馈
- N2.1: 在收到首个文本增量前，显示带动画与实时秒数的"处理中"指示（如 "Imagining… (5s)"）
- N2.2: 文本增量到达后尽快逐字呈现，给用户"实时打字"的观感

### N3: 跨协议一致体验
- N3.1: 无论使用 Anthropic 还是 OpenAI 协议，用户感知的输入、流式输出、多轮上下文与错误反馈行为保持一致

### N4: 配置健壮性
- N4.1: 配置文件缺失、YAML 格式错误、必要字段缺失等情况，给出明确可读的错误提示，而非崩溃堆栈

### N5: 密钥安全
- N5.1: API 密钥不在界面回显
- N5.2: API 密钥不打印到对话区或任何日志输出中

### N6: 终端兼容与自适应
- N6.1: 在常见终端下正常显示（macOS Terminal、iTerm2、Windows Terminal、Linux 终端）
- N6.2: Markdown 渲染与界面布局对终端宽度自适应，窄屏不错版

### N7: 退出整洁
- N7.1: 退出时恢复终端状态（清理 raw mode 等），不残留损坏的终端环境

## 不做的事

### 功能层面
- **工具调用 / function calling**：本期不发送工具定义、不处理工具调用，纯文本对话
- **MCP 集成**：不连接任何 MCP server（状态栏中的相关指示仅作视觉参考，不实现）
- **权限系统**：无任何需授权的操作，故不做权限确认
- **上下文压缩**：历史增长不做摘要/截断，超长由用户自行控制（留给后续章节）
- **长期记忆 / 跨会话记忆**：不做
- **会话持久化**：历史不落盘、不支持重启恢复或续聊
- **slash 命令体系**：除 /exit 外，不做可扩展的命令系统（如 /help、/clear、/model 等）
- **运行时切换 provider / model**：多份配置仅在启动时选一次，会话中途不切换
- **thinking 内容展示**：扩展思考增量接收即丢弃，不渲染、不折叠展示
- **流式中断**：本期不支持取消正在进行的回复
- **自动重试 / 限流退避**：出错仅提示，不自动重试
- **其它配置来源**：仅读 YAML 配置文件，不做环境变量 / 命令行 flag 覆盖
- **用量统计**：不显示 token 数与费用（但保留响应耗时计时）
- **多模态**：不支持图片等非文本输入

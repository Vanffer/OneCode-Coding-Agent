# OneCode Coding Agent - 基础对话功能 Checklist

> 每一项通过运行代码或观察行为来验证，聚焦系统行为。

## 编译与构建
- [ ] 项目编译无错误（验证：`go build ./...`）
- [ ] 所有单元测试通过（验证：`go test ./...`）

## 启动与配置
- [ ] 启动时正确加载配置文件，显示 ASCII art 风格的柴犬图案 + logo + 版本号 + 工作目录（验证：启动程序，观察输出）
- [ ] 配置文件缺失时，显示明确错误信息并退出（验证：删除配置文件后启动，观察错误信息）
- [ ] 配置文件格式错误时，显示明确错误信息并退出（验证：修改 YAML 为无效格式后启动，观察错误信息）
- [ ] 必要字段缺失时，显示明确错误信息并指明哪个 provider 的哪个字段（验证：删除 api_key 后启动，观察错误信息）
- [ ] 单 Provider 配置时直接进入对话界面（验证：配置只有一个 provider 后启动，观察直接进入对话）
- [ ] 多 Provider 时显示选择界面（验证：配置多个 provider 后启动，观察出现选择列表）
- [ ] 选择界面支持方向键导航、Enter 确认（验证：在选择界面按上下键移动、按 Enter 选定）
- [ ] API 密钥不在界面回显，不打印到对话区或日志（验证：观察整个界面，确认无密钥显示）

## TUI 界面布局
- [ ] 界面包含就绪提示行（验证：观察启动后的界面，显示 "Ready to help..."）
- [ ] 界面包含对话区（验证：观察界面中间区域用于显示对话）
- [ ] 界面包含输入框，显示 ❯ 提示符和 "Send a message..." 占位文字（验证：观察底部输入框）
- [ ] 界面包含状态栏，左侧显示活动 Provider 名称，右侧显示模型名称（验证：观察状态栏内容）
- [ ] Ctrl+C 正常退出，终端状态恢复，不残留损坏的终端环境（验证：按 Ctrl+C 退出后，终端可正常使用）

## 流式对话与渲染
- [ ] 用户输入问题后，AI 回复以 SSE 流式方式逐字显示（验证：输入问题，观察回复逐字出现）
- [ ] 流式输出期间界面不冻结，可滚动查看历史（验证：流式输出期间尝试滚动）
- [ ] 流式输出结束后，Markdown 内容正确渲染（验证：观察代码块高亮、列表缩进、表格对齐）
- [ ] 等待首个 token 期间显示 "Imagining… (Xs)" 实时计时（验证：发送消息后观察计时显示）
- [ ] 回复结束后定型显示该轮总耗时（验证：回复完成后观察耗时显示）
- [ ] 文本增量到达后尽快逐字呈现，给用户"实时打字"观感（验证：观察流式输出的实时性）

## 多轮对话
- [ ] 多轮对话时，AI 能正确引用之前的上下文，对话连贯（验证：进行多轮对话，观察 AI 是否记住之前的内容）
- [ ] 对话历史仅保留在内存中，退出后清空（验证：退出后重新启动，确认无历史记录）

## Provider 抽象层
- [ ] Anthropic 协议流式输出正常（验证：使用 Anthropic provider 进行对话）
- [ ] OpenAI 协议流式输出正常（验证：使用 OpenAI provider 进行对话）
- [ ] 两种协议的流式输出行为一致（验证：对比两种 provider 的对话体验）

## Extended Thinking
- [ ] 请求 Claude API 时按配置决定是否启用 extended thinking（验证：配置 thinking=true，观察请求是否包含 ThinkingConfig）
- [ ] thinking 增量接收即丢弃，不渲染、不折叠展示（验证：启用 thinking 后对话，确认界面无 thinking 内容）

## 错误处理
- [ ] API 调用失败时显示错误信息，不崩溃，可继续对话（验证：使用无效 API key，观察错误显示后可继续输入）
- [ ] 流式输出过程中断时，保留已输出内容，显示错误提示（验证：流式输出期间断网，观察已输出内容保留）
- [ ] 出错仅提示，不自动重试（验证：观察错误后无自动重试行为）

## 终端兼容
- [ ] 在 macOS Terminal 下正常显示（验证：在 macOS Terminal 中运行）
- [ ] 在 iTerm2 下正常显示（验证：在 iTerm2 中运行）
- [ ] 在 Windows Terminal 下正常显示（验证：在 Windows Terminal 中运行）
- [ ] 在 Linux 终端下正常显示（验证：在 Linux 终端中运行）
- [ ] Markdown 渲染与界面布局对终端宽度自适应，窄屏不错版（验证：调整终端宽度，观察界面自适应）

## 端到端场景
- [ ] 场景 1：单 Provider 完整对话流程 — 启动 → 输入问题 → 流式回复 → Markdown 渲染 → 继续对话 → 退出（验证：完成整个流程，无异常）
- [ ] 场景 2：多 Provider 选择流程 — 启动 → 选择 Provider → 对话 → 退出（验证：完成整个流程，无异常）
- [ ] 场景 3：错误恢复流程 — 启动 → 输入问题 → API 错误 → 显示错误 → 继续对话（验证：错误后可正常继续）
- [ ] 场景 4：长时间对话 — 启动 → 进行 5 轮以上对话 → 验证上下文连贯性（验证：多轮对话后 AI 仍能记住早期内容）

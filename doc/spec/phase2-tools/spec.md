# 工具系统 Spec

## 背景

OneCode 目前是一个纯聊天机器人——模型只能生成文本回复，无法与外部世界交互。用户问「帮我读一下 main.go」或「把这个函数改名」，模型只能猜测或拒绝。

## 目标

给 OneCode 装上工具系统，让模型能够：

- 读取、创建、修改文件
- 执行 shell 命令
- 搜索文件和代码内容
- 根据工具返回结果决定下一步行动

这一阶段实现**单次工具调用**：模型发起一次 tool_use → 代码执行 → 结果回灌 → 模型生成最终回复。自动循环（Agent Loop）留到下一章。

## 功能需求

### F1: 工具接口

定义统一的 Tool 接口，每个工具实现它。工具携带元信息：名称、描述、参数 JSON Schema。

### F2: 六个核心工具

| 工具 | 名称 | 职责 |
|------|------|------|
| 读文件 | read_file | 给定路径，返回文件文本内容（带行号便于引用）；文件不存在/不可读时返回结构化错误 |
| 写文件 | write_file | 创建或覆盖文件，自动创建父目录 |
| 改文件 | edit_file | 基于原文唯一匹配替换，匹配不到或多匹配时报错 |
| 执行命令 | bash | 给定 shell 命令，在工作目录下执行，受超时约束；返回 stdout、stderr 与退出码；超时或非零退出以结构化结果返回，不中断会话 |
| 按模式找文件 | glob | 给定 glob 模式，返回匹配的文件路径列表，支持指定子目录 |
| 搜代码内容 | grep | 给定搜索模式（与可选路径范围），在文件内容中检索，返回命中位置（文件/行/内容） |

### F3: 工具注册中心

集中登记所有工具，按名查找，提供方法将注册的工具转成 LLM API 认得的工具列表（JSON Schema 格式）。

### F4: 工具执行引擎

接收工具名 + JSON 参数，查找并执行工具。统一超时 30 秒，bash 5 分钟。失败时将完整错误信息（包括上下文细节）包成 ToolResult 返回。

### F5: 流式工具调用解析

LLM 客户端解析流式响应中的 tool_use 块。Anthropic 和 OpenAI 都支持。处理 JSON 参数碎片拼接，直到完整的工具调用就绪。

### F6: 工具结果回灌

工具执行结果以 tool_result 角色注入对话历史，然后发起新一轮请求让模型生成最终文本回复。

### F7: Message 模型扩展

扩展 Message 结构，支持 tool_use 和 tool_result 内容块，保持与纯文本消息的兼容。

### F8: TUI 呈现工具调用（Claude Code 风格）

在对话区以可区分的"工具行"展示每次工具调用：工具名 + 关键参数（如 `● Read(path)`、`● Bash(cmd)`），其后展示结果摘要；结果过长时截断/摘要呈现。工具行随流式实时出现，并纳入 scrollback 历史。

### F9: 错误作为结构化结果

工具执行失败（文件不存在、命令超时/非零退出、改文件匹配数不对、搜索无结果等）以结构化结果回灌给模型，模型可据此调整；同时在 UI 以可区分样式提示。程序不崩溃、会话不中断。本轮在这次最终答复后结束——即使模型在最终答复阶段又想调用工具，本章不再发起新一轮工具执行（连环调用/Agent Loop 留到下一章）。

## 非功能需求

### N1: 超时约束

- 默认工具超时：30 秒
- bash 工具超时：5 分钟
- 超时以结构化结果返回，不中断会话

### N2: 错误隔离

工具执行失败不影响程序运行。所有错误被捕获、结构化、返回给模型或展示在 UI。

### N3: 流式体验

工具调用信息随流式响应实时出现在 TUI，用户能感知模型正在做什么。

### N4: 向后兼容

Message 结构扩展后，纯文本对话（无工具调用）的行为不变。

### N5: 单轮约束

本轮只做一次工具调用循环：模型发起 tool_use → 执行 → 结果回灌 → 最终回复。即使模型在最终回复中再次请求工具调用，也不执行。Agent Loop 留到下一章。

### N6: 结果体量控制

大文件/长输出有上限或截断：读文件行数上限、命令输出截断、搜索结果条数上限。避免撑爆上下文或界面。

### N7: 密钥安全

API 密钥不回显、不打印到对话区或任何输出中。

## 不做的事

- **Agent Loop / 连环调用**：模型拿到一次工具结果后生成最终回复，不再循环。自动循环留到下一章。
- **并行工具调用**：本轮只处理单个 tool_use，不处理模型同时发起多个工具调用的情况。
- **多模态工具结果**：工具结果均为文本，不含图片等非文本产物。
- **工具行的折叠/展开交互**：UI 仅展示工具行 + 结果摘要，不做可交互折叠或详情展开。
- **工具调用与结果持久化**：工具调用与结果不落盘，退出即丢。
- **工具调用中断/取消**：本章不支持中途取消正在执行的工具或正在进行的回复。
- **权限系统**：工具执行（含写文件、执行命令）本章不做授权确认，仅靠超时与结构化错误约束。
- **工具执行沙箱/路径白名单**：不限制工具只能在工作目录内操作；不做路径越界防护。
- **MCP / 外部工具协议**：只做内置工具，不支持外部工具服务。

## 验收标准

| ID | 对应需求 | 验收标准 | 验证方式 |
|----|---------|---------|---------|
| AC1 | F1/F3 | 注册中心能列出全部已注册工具并按名查找；导出的工具定义随请求发送 | 单测 + 抓取请求体含 6 个工具定义 |
| AC2 | F2-read_file | 读出指定文件内容（带行号）；读不存在文件返回结构化错误而非崩溃 | 分别读存在/不存在的文件 |
| AC3 | F2-write_file | 创建/覆盖文件内容正确落地；父目录不存在时自动创建 | 写新文件 + 写嵌套路径后检查磁盘 |
| AC4 | F2-edit_file | 唯一匹配替换成功；匹配 0 次与多于 1 次分别返回可区分的错误信息 | 三种情形各跑一次，看返回 |
| AC5 | F2-bash | 执行命令返回 stdout/stderr/退出码；故意超时的命令被超时终止并返回超时结果，会话不挂死 | 跑 `echo` 与超时命令各一次 |
| AC6 | F2-glob | glob 模式能列出匹配文件 | 用 `**/*.go` 搜一次 |
| AC7 | F2-grep | 内容搜索能返回命中位置（文件/行/内容） | 用某关键字搜一次 |
| AC8 | F4/F5 | 一次需要用工具的提问下，能从流式回复中拼接出完整的工具名与 JSON 参数 | 问「读 X 文件」，观察解析出的工具调用正确 |
| AC9 | F6 | 端到端：问「读 X 文件并总结」→ 模型调用读文件 → 结果回灌 → 模型据此给出最终文本总结 | 跑通整条链路，答复体现文件内容 |
| AC10 | F9/N5 | 本章只执行一轮工具调用；第一轮结果回灌后若模型仍请求工具，不再发起新一轮 | 给需连续两步工具的任务，观察在一轮工具后停止 |
| AC11 | F7 | 分别用 Anthropic 与 OpenAI 配置跑同一组工具任务，触发、展示、结果回灌、错误反馈行为一致 | 两种协议各跑一次相同任务 |
| AC12 | F8 | 工具调用在对话区以 `● 工具名(关键参数)` 工具行 + 结果摘要展示，过长结果截断，纳入 scrollback | 跑一次工具任务后回滚查看 |
| AC13 | F9/N2 | 故意触发各类工具失败（不存在文件、命令非零退出、改文件匹配不到），均以结构化结果回灌且 UI 可区分提示，程序不崩溃、会话可继续 | 逐个触发后再正常发一条 |
| AC14 | N4 | 无工具调用的纯文本对话行为与改动前一致 | 不触发工具的普通聊天正常 |
| AC15 | N6 | 超大文件/超长命令输出/海量搜索结果被截断处理，不撑爆界面或上下文 | 读大文件、跑长输出命令观察截断 |
| AC16 | N7 | API 密钥不出现在对话区或任何用户可见输出中 | 检查所有输出路径 |

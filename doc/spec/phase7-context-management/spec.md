# 上下文管理能力 Spec

## 背景

OneCode 已经具备多轮对话、工具调用、Agent 循环执行、权限控制、Prompt Runtime 和 MCP 工具接入能力。随着 Agent 连续执行任务，历史消息、工具调用结果、运行时提醒和模型回复会持续累积，最终可能逼近或超过模型的上下文窗口上限。

当前最大风险来自工具结果。读大文件、搜索大量匹配、执行命令输出日志、调用 MCP 工具返回大量内容时，单次工具结果就可能占用大量上下文。即使模型当前能继续工作，后续循环也会因为历史不断变长而变得不稳定，最终出现请求失败或不得不丢失上下文。

OneCode 需要一套上下文管理能力，让 Agent 在有限 Token 预算内长时间运行。系统应优先控制工具结果带来的上下文膨胀，同时在整体对话接近窗口上限时进行结构化压缩。用户原始消息应尽量保留原文，避免被摘要改写导致需求细节丢失。

此外，用户需要在 TUI 中持续看到上下文窗口使用情况，并能够可视化调整当前项目的上下文窗口大小，使 OneCode 在默认易用的同时，也能适配国产模型、代理模型和第三方兼容模型的不同上下文限制。

## 目标

- 让 OneCode 在长时间 Agent 运行中主动控制上下文增长，降低因为上下文超限导致任务中断的概率。
- 优先压缩或转移大工具结果，避免单次工具输出直接污染后续所有对话上下文。
- 在整体对话接近窗口上限时，通过结构化摘要保留长期任务状态，同时保留近期原文消息。
- 尽量保持用户原始消息不被摘要改写，减少需求、约束和偏好丢失。
- 让被转移的完整工具结果可以被重新读取，避免只截断导致信息不可恢复。
- 支持用户手动触发上下文压缩。
- 在压缩连续失败时停止自动重试，避免压缩死循环。
- 在 API 因上下文过长拒绝请求后，提供一次紧急压缩和重试机会。
- 在 TUI 中常驻展示上下文窗口使用情况。
- 在任意方式触发上下文压缩时，在 TUI 中展示相应状态提示，让用户知道当前正在压缩、压缩已完成或压缩失败。
- 默认自动推断上下文窗口大小，并允许用户在 TUI 中可视化调整和保存当前项目的本地窗口设置。

## 功能需求

- F1: 系统应在每次向模型发起正常请求前，先检查当前对话中的工具结果大小，并对超过阈值的工具结果进行轻量处理。

- F2: 当单个工具结果超过单项阈值时，系统应将完整结果保存到当前项目的 OneCode 管理目录，并在对话中只保留内容预览、保存位置和可重新读取的提示。

- F3: 当同一轮消息中的多个工具结果合计超过单轮阈值时，系统应优先处理较大的工具结果，直到该轮消息保留在对话中的工具结果总量不超过阈值。

- F4: 系统应尽量保留用户原始消息的原文，不应把用户消息作为轻量工具结果处理的一部分改写或存盘替换。

- F5: 系统应在整体对话接近上下文窗口上限时，自动触发重量压缩，将较早的对话内容替换为结构化摘要，并保留近期原文消息。

- F6: 重量压缩生成的摘要应包含固定结构，用于保留任务目标、用户约束、已完成工作、关键决策、重要文件或路径、未完成事项、风险和后续建议。

- F7: 重量压缩时，系统应保留最近一段原文上下文；保留范围应以最近 Token 预算为主，并保证至少保留若干条最近消息。

- F8: 重量压缩结果应包含近期访问过、编辑过或由工具结果引用过的重要文件索引。索引应包含文件路径、简短内容预览和相关上下文提示，帮助模型在压缩后知道哪些文件值得重新读取；索引应控制大小，不应把大文件完整内联进摘要。

- F9: 重量压缩请求应明确禁止模型调用工具，并要求模型先进行分析草稿，再输出正式摘要；草稿不应进入后续对话上下文。

- F10: 压缩完成后，系统应在新的上下文中加入边界提示，提醒模型摘要可能不包含全部细节；如果需要具体内容，应重新读取保存的工具结果或相关文件，不得根据摘要虚构细节。

- F11: 用户应能通过手动命令触发上下文压缩。手动压缩应使用更激进的压缩触发策略，但仍需保留近期原文消息和用户原始需求。

- F12: 当正常请求因为上下文过长被模型服务拒绝时，系统应触发一次紧急压缩，并在压缩成功后重试原请求；如果重试后仍失败，应按正常错误展示，不应无限重试。

- F13: 当自动上下文压缩连续失败达到限制次数时，系统应停止继续自动压缩，避免进入反复压缩失败的循环。手动压缩和紧急压缩仍应给出清晰失败提示。

- F14: 系统应默认自动推断上下文窗口大小；当无法可靠推断时，应使用保守默认值，确保 OneCode 在没有用户手动配置窗口大小时仍可运行。

- F15: 用户应能在 TUI 中可视化查看和调整当前项目的上下文窗口大小，调整结果应保存为当前项目的本地配置，不默认进入项目共享配置。

- F16: TUI 应常驻展示当前上下文窗口使用情况，包括已使用量、窗口上限和使用比例；当窗口大小来自估算或保守默认值时，应能让用户感知该值可能不精确。

- F17: 当任意方式触发上下文压缩时，TUI 应展示对应状态提示，包括压缩开始、压缩完成、压缩失败、自动压缩熔断和紧急压缩重试等状态。

- F18: 上下文管理应使用近似 Token 估算即可；系统应优先复用最近一次模型服务返回的真实用量，并只对新增内容进行近似估算。

- F19: 上下文管理不应改变工具执行本身的语义。工具仍应正常执行，轻量处理只影响工具结果进入后续对话上下文的形式。

## 非功能需求

- N1: 上下文管理应尽量避免丢失可恢复信息。被轻量处理的大工具结果应保留完整内容，并能通过保存位置重新读取。

- N2: 上下文管理应优先保护用户输入的原始语义。用户消息、明确约束、偏好、任务目标和验收要求不应被随意删改或只保留含糊摘要。

- N3: 压缩后的上下文应避免诱导模型虚构。摘要、文件索引和边界提示都应明确区分“已知事实”“可重新读取的位置”和“需要重新确认的细节”。

- N4: Token 用量估算允许近似，但应保持稳定、可解释，并优先使用模型服务返回的真实用量作为锚点，避免随着对话增长产生越来越大的估算偏差。

- N5: 自动压缩不应频繁打断正常 Agent 流程。系统应在请求前完成必要检查，并尽量减少对工具执行、流式输出和用户交互体验的影响。

- N6: 压缩失败应可控。连续失败后应停止自动压缩，并通过 TUI 给出清晰提示，不应进入无限重试或反复请求模型的状态。

- N7: 紧急压缩应只作为上下文超限后的补救机制，不应无限重试。一次紧急压缩和重试仍失败时，应向用户展示明确错误。

- N8: 项目本地保存的上下文管理产物应与当前项目绑定，不应污染其他项目，也不应默认进入项目共享配置或版本控制内容。

- N9: TUI 中的上下文窗口展示应轻量、常驻、易理解，不应遮挡主要对话内容；压缩状态提示应能让用户知道系统当前是在正常工作、压缩中、已完成、失败或已熔断。

- N10: 可视化配置上下文窗口大小时，应兼顾默认易用和高级控制。用户不配置时系统仍可运行；用户调整后应在当前项目后续会话中生效。

- N11: 上下文管理能力应兼容不同模型供应商、第三方兼容接口和国产模型接入方式，不应依赖某一家模型服务的专有能力才能完成基本工作。

- N12: 上下文管理不应改变现有权限边界。保存、读取或提示重新读取上下文相关内容时，仍应遵守 OneCode 当前的项目边界和权限策略。

## 不做的事

- 本阶段不实现精确 Tokenizer。系统只需要使用近似估算，并结合最近一次模型服务返回的真实用量进行校准。

- 本阶段不做摘要策略的机器学习优化、自动评估模型或多摘要候选选择。摘要策略采用固定结构和明确提示词。

- 本阶段不保证所有历史原文永久保留。整体对话压缩时，较早消息可以被结构化摘要替换，但用户近期消息和关键约束应尽量保留。

- 本阶段不把用户原始消息作为轻量压缩对象进行单独存盘替换。轻量处理优先针对工具结果。

- 本阶段不实现跨项目共享的上下文产物管理。保存的大工具结果、上下文窗口本地设置和压缩相关产物都应绑定当前项目。

- 本阶段不实现复杂的长期记忆系统、向量检索系统或跨会话知识库。上下文管理只服务于当前项目和当前对话连续运行。

- 本阶段不要求自动识别所有模型的真实上下文窗口。系统可以自动推断常见模型，并允许用户覆盖；无法识别时使用保守默认值。

- 本阶段不实现复杂的上下文用量详情面板。TUI 需要常驻展示基本使用情况和压缩状态提示；更细的分解统计可以留到后续增强。

- 本阶段不改变工具权限模型。上下文管理产生的保存、读取和提示行为仍应遵守现有项目边界和权限策略。

- 本阶段不要求支持二进制、大型媒体或富格式工具结果的完整预览。此类内容可以保存完整结果，并在对话中保留路径和简短说明。

## 验收标准

- AC1: 当单个工具结果超过单项阈值时，完整结果被保存到当前项目的 OneCode 管理目录；后续对话中只包含预览、保存位置和重新读取提示。

- AC2: 当同一轮多个工具结果合计超过单轮阈值时，系统优先处理较大的工具结果，直到该轮保留在对话中的工具结果总量不超过阈值。

- AC3: 轻量处理后，用户原始消息仍保留原文，不会因为工具结果过大而被替换成摘要或路径提示。

- AC4: 当整体对话接近上下文窗口上限时，系统自动触发重量压缩；压缩后较早内容被结构化摘要替换，近期原文消息仍保留。

- AC5: 压缩摘要包含固定结构，至少覆盖任务目标、用户约束、已完成工作、关键决策、重要文件或路径、未完成事项、风险和后续建议。

- AC6: 压缩后上下文中包含近期访问、编辑或由工具结果引用过的重要文件索引；索引包含文件路径、简短内容预览和相关上下文提示，且不会把大文件完整内联进摘要。

- AC7: 重量压缩请求不会允许模型调用工具；分析草稿不会进入后续对话上下文，后续对话只保留正式摘要。

- AC8: 压缩后上下文包含边界提示，提醒模型需要具体细节时重新读取保存的工具结果或相关文件，并禁止根据摘要虚构细节。

- AC9: 用户执行手动压缩命令后，系统触发上下文压缩；压缩完成后 TUI 展示完成提示，并继续使用压缩后的上下文对话。

- AC10: 当正常请求因上下文过长被拒绝时，系统触发一次紧急压缩并重试原请求；如果重试仍失败，TUI 展示明确错误，不再无限重试。

- AC11: 当自动压缩连续失败达到限制次数后，系统停止自动压缩，并在 TUI 中展示自动压缩已熔断的提示。

- AC12: 在未配置上下文窗口大小时，系统仍能启动并展示上下文使用情况；如果窗口大小来自估算或保守默认值，TUI 能体现该值可能不精确。

- AC13: 用户可以在 TUI 中可视化调整当前项目的上下文窗口大小；重启 OneCode 后，该项目仍使用调整后的窗口大小。

- AC14: TUI 常驻展示上下文窗口使用情况，包括已使用量、窗口上限和使用比例。

- AC15: 任意方式触发上下文压缩时，TUI 展示相应状态提示，至少覆盖压缩开始、压缩完成、压缩失败、紧急压缩重试和自动压缩熔断。

- AC16: 系统优先使用最近一次模型服务返回的真实用量作为估算锚点；新增内容使用近似估算，并能反映在 TUI 的上下文使用量中。

- AC17: 上下文管理不改变工具执行结果的原始语义；被轻量处理的工具结果仍能通过保存位置恢复完整内容。

- AC18: 项目本地保存的上下文产物和上下文窗口本地设置只影响当前项目，不默认写入项目共享配置。

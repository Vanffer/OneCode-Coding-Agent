# 持久会话与长期记忆 Spec

## 背景

OneCode 已具备多轮 Agent Loop、工具调用、权限控制、结构化提示词、MCP 接入和当前会话的上下文压缩能力。但这些能力主要服务于正在运行的进程：程序退出后，对话历史不能继续恢复；新会话也不会自动获得此前积累的项目知识和用户偏好。

这会产生三类“失忆”问题：

- 项目约定需要用户在每次会话中重新说明。
- 长任务因退出、崩溃或主动中断后难以平滑继续。
- Agent 从用户纠正和项目实践中获得的经验无法跨会话复用。

本阶段建立三层持久上下文：

- 项目指令：加载用户手写的长期规则、项目约定和注意事项。
- 会话存档：持久保存完整消息历史，并允许用户主动继续或选择历史会话。
- 自动记忆：从有长期价值的对话中提取用户偏好和项目知识，在未来请求前注入精简索引。

## 目标

- 普通启动始终进入新会话，不自动混入旧会话历史。
- 用户可以继续最近会话，也可以从历史列表中选择会话恢复。
- 会话在异常中断后能够尽可能恢复到最后一个完整且结构合法的状态。
- 新会话自动获得当前项目指令、用户长期偏好和项目长期知识。
- 自动记忆在后台更新，不阻塞 Agent 的最终回复和正常交互。
- 项目知识与用户偏好分层存储，减少跨项目污染。
- 控制长期上下文的注入规模，避免记忆内容挤占主要任务上下文。
- 所有持久化内容保持本地、可检查、可编辑和可删除。

## 功能需求

### 项目指令

- F1：每次创建新会话或恢复历史会话时，系统应加载三层项目指令：`项目/.onecode/ONECODE.md`、`项目根/ONECODE.md`、`~/.onecode/ONECODE.md`。
- F2：项目指令应按照 `项目/.onecode/ONECODE.md`、`项目根/ONECODE.md`、用户级文件的优先级排列，高优先级内容排在前面；文件不存在时正常跳过。
- F3：项目指令应支持通过 `@include` 引用其他文本文件，引用可以递归展开，最大嵌套深度为 5。
- F4：系统应使用已访问集合防止重复加载和循环引用；同一个真实文件在一次加载过程中最多展开一次。
- F5：项目级指令只能引用项目根目录以内的文件；用户级指令只能引用 `~/.onecode/` 以内的文件。安全检查应考虑相对路径、`..`、绝对路径和符号链接逃逸。
- F6：当引用文件不存在、无法读取、超过深度、形成循环或越过安全边界时，系统应跳过该引用、展示明确警告，并继续加载其他有效指令。
- F7：加载完成的项目指令应在模型处理当前会话请求前进入上下文；本阶段不改变现有 Provider 的消息角色和 reminder 传输方式。

### 会话存档

- F8：普通启动应始终创建一个新会话，不自动恢复历史会话。新会话 ID 使用 `YYYYMMDD-HHMMSS-xxxx` 格式，其中随机后缀用于避免同一秒内发生冲突。
- F9：会话文件应保存到 `项目/.onecode/sessions/`，每个会话对应一个 JSONL 文件，并默认排除在 Git 版本控制之外。
- F10：会话应按完整消息追加写入，包括用户消息、助手消息、助手工具调用和工具结果。流式文本增量不逐块持久化。
- F11：用户消息在提交时立即保存；助手消息在该轮响应完整收集后保存；工具结果在执行完成后分别保存。进程在流式响应中途崩溃时，允许丢失当前未完成的助手响应，但已完成消息必须保留。
- F12：会话记录应包含足够信息，以便恢复用户、助手和工具消息之间的顺序与关联，并能恢复上下文压缩后模型实际可见的有效历史。
- F13：系统不得单独维护需要与 JSONL 同步的会话元数据文件。会话 ID、标题、创建时间、最后活动时间和消息数应在需要时通过扫描 JSONL 获得。
- F14：会话标题应取第一条非空用户消息的首行，合并连续空白后截取约 60 个字符；没有有效用户消息时使用会话 ID 作为标题。
- F15：系统应提供 `/continue`，用于恢复当前项目最近一次有效且未过期的会话。
- F16：系统应提供 `/resume`，展示当前项目的历史会话列表。列表至少显示标题、更新时间和消息数，并允许用户选择要恢复的会话。
- F17：恢复会话后，后续消息应继续追加到原 JSONL 文件，不自动复制或创建新的会话 ID。
- F18：扫描或恢复 JSONL 时，无法解析的单行记录应被跳过并产生警告；其他合法记录应继续恢复，不因单个坏行丢弃整个会话。
- F19：恢复时应验证工具调用和工具结果的配对关系。发现缺失结果、顺序错误或无法关联的工具交互时，应保留最长合法消息前缀，从出现问题的助手工具调用轮次开始截断后续历史。
- F20：恢复后的上下文如果超过当前模型窗口，应先尝试执行一次上下文压缩。压缩成功后继续恢复；压缩失败时应报告错误且不得无限重试，原始会话文件不得被破坏。
- F21：如果会话最后一次有效活动距离当前时间超过 24 小时，系统应在恢复后的第一次模型请求中临时注入时间跨度提醒，提示模型重新检查可能变化的仓库和外部状态。该提醒不写入 JSONL、不显示成用户消息，也不修改恢复出的历史。
- F22：系统应定期清理最后有效活动时间超过 30 天的会话文件。清理不得删除当前正在使用的会话；单个文件删除失败不应阻止程序启动或其他会话恢复。

### 自动记忆

- F23：自动记忆默认开启，并允许通过配置关闭。关闭后停止读取、注入和生成自动记忆，但不删除已有记忆文件。
- F24：项目级记忆应保存到 `项目/.onecode/memory/`，用户级记忆应保存到 `~/.onecode/memory/`。项目级自动记忆默认排除在 Git 版本控制之外。
- F25：自动记忆应支持用户偏好、纠正反馈、项目知识和参考资料四种分类。
- F26：用户明确表达的跨项目长期偏好可以写入用户级记忆；当前仓库的架构、命令、约定和纠正应写入项目级记忆。作用域不明确时应优先写入项目级或不记录，不得根据一次临时要求推断全局偏好。
- F27：Agent Loop 以无工具调用的最终回复自然结束后，系统应异步提交记忆候选任务。取消、流错误、迭代上限和异常终止不得触发自动记忆生成。
- F28：提交 LLM 判断前，系统应使用本地轻量规则跳过明显过短、完全重复或没有长期价值信号的轮次，减少无意义的额外模型调用。
- F29：记忆更新任务应串行执行，避免多个异步任务同时读取旧索引后创建重复笔记；记忆更新不得阻塞最终回复展示和下一轮正常对话。
- F30：记忆更新只支持 `skip`、`create` 和 `update` 三种结果。语义相同的信息不得重复创建笔记；补充、重复或纠正已有信息时应更新已有笔记。
- F31：每条笔记应使用一个带 frontmatter 的 Markdown 文件，至少记录稳定标识、分类、作用域、标题、创建时间和更新时间。
- F32：用户级和项目级记忆应分别维护索引文件。索引应包含足以让模型了解已有记忆的简短摘要和对应笔记位置，不应把全部笔记正文复制进索引。
- F33：每份索引文件自身不得超过 200 行或 25KB；在一次模型请求中，用户级与项目级索引的合计注入量不得超过 200 行或 25KB，并应为用户级偏好预留最低空间。
- F34：记忆索引应在模型处理请求前进入上下文，使 Agent 无需先执行额外检索即可了解主要用户偏好和项目知识。超出索引预算的详细笔记保留在磁盘，但本阶段不实现自动语义检索。
- F35：记忆更新过程中，去重和语义合并由 LLM 在已有索引约束下判断；完全相同的候选内容应优先由本地逻辑直接跳过。
- F36：系统不得把 API Key、访问令牌、密码、私钥或其他明显凭据写入自动记忆。写入前应执行本地敏感信息检查，发现疑似凭据时跳过或移除敏感部分。
- F37：自动记忆调用或文件写入失败时，不得影响已完成的用户回复和 Agent Loop；系统应保留可观察的错误信息，供用户排查。
- F38：自动记忆的索引更新应与笔记写入保持一致。只有笔记成功写入后才能更新索引，失败时不得留下指向不存在文件的索引项。

## 非功能需求

### 可靠性与一致性

- N1：会话 JSONL 的每一行必须是独立、完整且可单独解析的记录。进程崩溃或写入中断时，损坏范围应尽量限制在最后一条正在写入的记录。
- N2：会话恢复必须具有确定性。同一份未变化的 JSONL 在相同配置下重复恢复，应得到相同的合法消息历史和相同的截断位置。
- N3：记忆笔记和索引的更新不得产生半完成状态。程序在更新过程中中断时，已有有效笔记和索引仍应保持可读取。
- N4：同一会话文件和同一记忆存储不得被多个后台任务无序并发写入。异步处理应保持消息、笔记和索引更新顺序稳定。
- N5：会话恢复、记忆更新或过期清理中的局部失败不得损坏原始文件，也不得导致其他独立会话或记忆无法使用。

### 性能与资源

- N6：普通新会话启动不应读取所有历史会话正文。历史扫描只在 `/continue`、`/resume`、过期清理或其他确有需要的场景执行。
- N7：会话列表扫描应能够处理大量 JSONL 文件，不应要求一次性把所有会话正文全部保留在内存中。
- N8：流式模型输出不得按文本增量频繁写盘。持久化粒度应控制在完整消息级，避免大量小写入和 JSONL 膨胀。
- N9：自动记忆更新必须异步执行，并设置有限的执行时间和队列边界。记忆服务变慢或失败不得拖慢用户看到最终回复的时间。
- N10：长期记忆进入模型上下文的规模必须受统一预算约束。笔记数量增长后，单次请求的自动注入量仍不得无限增长。

### 安全与隐私

- N11：项目指令引用的路径校验必须基于规范化后的真实路径，不能只做字符串前缀判断；符号链接、父目录跳转和路径前缀碰撞均不得绕过边界。
- N12：项目级指令和项目记忆只能影响当前项目；用户级记忆可以跨项目使用，但必须遵守保守写入规则，避免项目知识污染全局偏好。
- N13：`ONECODE.md` 和自动记忆属于模型上下文，不属于强制安全策略。它们不得覆盖系统安全边界、权限规则、工具限制和用户当前明确指令。
- N14：自动记忆不得故意保存凭据或明显敏感信息。敏感信息检查失败时应优先放弃该条笔记，而不是冒险持久化。
- N15：所有会话和记忆默认保存在本地。除正常调用已配置的 LLM 进行记忆判断外，本阶段不得主动上传存档或记忆文件到其他服务。
- N16：会话和记忆文件使用可读文本格式，用户可以直接检查、备份、编辑或删除，不依赖专有数据库工具。

### Prompt 与模型兼容性

- N17：项目指令、记忆索引和时间跨度提醒的注入不得要求某一家模型服务的专有能力。OpenAI、Anthropic 和兼容接口应保持相同行为语义。
- N18：本阶段不得为记忆功能重构现有 Provider 消息角色。动态内容继续复用现有 reminder 和消息拼装机制。
- N19：稳定 System Prompt 在同一运行期间应保持稳定。记忆索引、恢复提醒和其他变化内容不得反复改写稳定提示词主体，避免无谓破坏缓存前缀。
- N20：自动记忆使用的 LLM 输出必须经过结构和字段校验。格式错误、未知操作、非法路径或越界作用域不得直接写入文件。

### 可维护性与可观察性

- N21：项目指令、会话存档和自动记忆应保持独立职责和单向依赖，任一能力关闭或失败时，其他能力仍可工作。
- N22：警告和错误应包含足够定位信息，例如涉及的指令文件、会话 ID、JSONL 行号、记忆笔记或失败阶段，同时不得把检测到的凭据内容原样打印到日志。
- N23：时间、随机 ID、文件系统位置和记忆 LLM 调用应能够在测试中替换或控制，使过期清理、恢复截断和异步去重行为可以稳定验证。
- N24：实现应复用现有上下文估算与压缩能力，不应建立另一套相互冲突的 Token 计算和压缩状态。
- N25：会话恢复后的消息必须继续符合现有工具调用协议、权限系统和 Agent Loop 约束，不得因为从磁盘加载而绕过运行时权限检查。

## 不做的事

- 本阶段不实现向量数据库、Embedding、语义搜索、RAG 检索或基于相似度的自动笔记召回。
- 本阶段不在请求时自动读取所有详细笔记。模型只自动获得受预算限制的用户级和项目级索引。
- 本阶段不实现团队记忆、组织级记忆、跨设备同步、云端备份或多人协同编辑。
- 本阶段不对会话和记忆文件进行加密。用户应依赖本机文件权限保护这些本地数据。
- 本阶段不保证识别所有可能形式的敏感信息。系统只拦截常见凭据格式，不把检测能力描述为完整的数据防泄漏系统。
- 本阶段不实现记忆的周期性全库重整、置信度评分、证据次数、自动删除、自动遗忘或跨笔记冲突图。
- 本阶段不实现 `/memory` 图形化管理界面，也不提供笔记浏览、编辑、合并和删除对话框。用户可以直接检查和编辑 Markdown 文件。
- 本阶段不实现基于多次隐含行为自动升级全局偏好。只有明确表达的长期跨项目偏好才允许写入用户级记忆。
- 本阶段不让自动记忆任务在取消、流错误、迭代上限或其他异常停止后运行。
- 本阶段不为自动记忆单独选择模型，也不实现根据价格、额度或负载自动切换记忆模型。记忆更新使用当前会话已配置的 Provider。
- 本阶段不实现 Codex 式延迟空闲整理、额度阈值控制或多阶段 extraction/consolidation 流水线，只做本地筛选后的一次异步记忆判断。
- 本阶段不让自动记忆修改手写的 `ONECODE.md`。项目指令始终由用户维护，自动知识只写入 memory 目录。
- 本阶段不递归发现任意目录下的 `ONECODE.md`，也不实现按文件路径动态加载子目录规则。只加载约定的三份入口文件及其显式 `@include`。
- 本阶段不热更新项目指令。运行期间修改 `ONECODE.md` 后，需要创建或恢复会话时重新加载。
- 本阶段不实现 AI 生成会话标题、`/rename`、会话分叉、归档、导入、导出或全文搜索。
- 本阶段不按流式 Token 或文本片段保存助手回复，也不保证恢复模型中途生成但尚未完整收集的文本。
- 本阶段不维护独立的会话 meta 文件、会话索引数据库或 SQLite 投影；会话列表信息直接从 JSONL 扫描获得。
- 本阶段不实现多个 OneCode 进程同时操作同一项目时的完整跨进程锁和冲突合并。单进程内部应保证顺序与一致性，文件替换应尽量保持原子性。
- 本阶段不自动修复用户手工破坏的 Markdown frontmatter 或严重损坏的整个 JSONL 文件；系统只做安全跳过、最长合法前缀恢复和明确告警。
- 本阶段不改变现有权限模式、工具调度、Provider 消息角色和上下文压缩策略，只在既有能力上接入持久化与记忆。

## 验收标准

### 项目指令

- AC1：同时存在三份 `ONECODE.md` 时，新建或恢复会话后，模型上下文中的排列顺序为项目 `.onecode` 文件、项目根文件、用户级文件；删除任意一份后，系统仍能正常启动并加载其余文件。
- AC2：入口文件通过 `@include` 引用多层文件时，系统能够正确展开不超过 5 层的合法引用；同一文件被重复引用或形成环路时，该文件不会被无限展开。
- AC3：项目指令尝试通过 `..`、绝对路径或符号链接引用项目外文件时，该引用被拒绝并显示警告；其他合法指令仍正常加载。
- AC4：引用文件不存在、不可读或超过最大深度时，启动过程继续进行，警告中能够看出失败文件和失败原因。
- AC5：用户向模型提出与项目约定有关的问题时，模型请求中已经包含加载后的项目指令，不需要先调用工具读取 `ONECODE.md`。

### 会话持久化与恢复

- AC6：普通启动 OneCode 时创建全新会话，不自动出现上一会话历史；新会话 ID 符合 `YYYYMMDD-HHMMSS-xxxx` 格式。
- AC7：完成一次包含用户消息和助手回复的对话后，项目 `.onecode/sessions/` 中出现对应 JSONL 文件，并且每个完整消息都是独立可解析的记录。
- AC8：执行一次包含工具调用的任务后，JSONL 能表示助手工具调用、对应工具结果和最终助手回复；恢复后消息顺序和关联关系与原会话一致。
- AC9：模拟在流式响应完整结束前中断程序后重新恢复，会话最多丢失当前未完成的助手响应，之前已经完整写入的消息仍然存在。
- AC10：历史会话没有独立 meta 文件时，`/resume` 仍能展示由 JSONL 扫描得到的标题、更新时间和消息数；标题来自第一条非空用户消息的首行并受到长度限制。
- AC11：存在多个历史会话时，执行 `/continue` 恢复当前项目最后活动时间最新的有效会话；没有有效会话时给出明确提示并保持当前新会话可用。
- AC12：执行 `/resume` 时显示当前项目会话列表；选择一个会话后，TUI 显示其有效历史，并将后续消息继续追加到被选择的原文件。
- AC13：在会话 JSONL 中插入一条格式损坏的记录后，恢复过程跳过该行、显示包含行号的警告，并继续恢复其他合法记录。
- AC14：构造一个只有助手工具调用但缺少工具结果的会话时，恢复结果停在该工具调用之前的最长合法消息前缀，模型不会收到悬空工具调用。
- AC15：构造工具结果 ID 不匹配或工具结果顺序非法的会话时，系统进行相同的合法前缀截断，并且不改写原始 JSONL 文件。
- AC16：恢复出的历史超过当前模型上下文窗口时，系统只尝试一次恢复压缩；压缩成功后会话可继续，压缩失败时显示错误且不反复请求模型。
- AC17：恢复最后活动时间超过 24 小时的会话后，第一次模型请求包含时间跨度提醒；后续请求不再重复该提醒，JSONL 和 TUI 用户消息中也不存在这条内部提醒。
- AC18：准备一个最后有效活动时间超过 30 天的非活动会话后，运行定期清理会删除该会话；当前活跃会话和未过期会话不会被删除。
- AC19：项目生成会话文件后，Git 状态不会默认把 `.onecode/sessions/` 内容作为待提交项目文件展示。

### 自动记忆

- AC20：未关闭自动记忆时，一轮具有长期价值且自然结束的对话会异步产生或更新记忆；用户看到最终回复不需要等待记忆调用完成。
- AC21：配置关闭自动记忆后，已有记忆文件保持不变，新请求不注入记忆索引，Agent 自然结束后也不产生新的记忆更新。
- AC22：用户明确表达跨项目长期偏好时，笔记进入用户级 memory；当前仓库的构建命令、架构约定或纠正进入项目级 memory；含义不清的信息不会冒险写入用户级。
- AC23：取消、模型流错误、Agent 迭代上限或其他异常停止后，不会启动该轮自动记忆更新。
- AC24：明显过短、完全重复或没有长期价值信号的轮次被本地筛选跳过，不会产生额外的记忆 LLM 请求。
- AC25：首次出现有价值信息时，记忆更新可以创建新笔记；再次表达相同信息时不会创建重复文件；提供更具体的信息时会更新原笔记。
- AC26：连续快速完成多轮可能产生同一记忆的对话时，后台更新按照轮次串行处理，最终不会因为并发读取旧索引而创建多份重复笔记。
- AC27：创建的笔记是带有效 frontmatter 的 Markdown，至少可以观察到标识、分类、作用域、标题、创建时间和更新时间。
- AC28：用户级与项目级分别存在索引文件；索引项包含笔记摘要和位置，但不复制全部笔记正文。
- AC29：当两层索引内容增长时，每份磁盘索引不超过 200 行或 25KB；单次模型请求中实际注入的两层索引合计也不超过该限制，并且用户级偏好不会被项目索引完全挤出。
- AC30：存在记忆索引时，新会话的第一次正常模型请求已经包含主要用户偏好和项目知识；模型不需要先执行额外检索才能知道这些摘要。
- AC31：记忆候选中包含常见 API Key、访问令牌、密码或私钥格式时，敏感内容不会写入笔记、索引或错误日志。
- AC32：记忆 LLM 返回未知操作、非法字段、非法作用域或越界文件位置时，系统拒绝写入并记录可定位的错误。
- AC33：模拟笔记写入失败时，索引不会新增指向不存在文件的条目；用户已完成的回复和后续 Agent 对话不受影响。
- AC34：模拟索引更新失败时，原有索引仍可读取，已经存在的其他笔记不被损坏，并产生可观察的错误信息。

### 集成行为

- AC35：项目指令、记忆索引和时间跨度提醒接入后，OpenAI 与 Anthropic Provider 均能继续完成普通文本回复和工具调用，不要求新增专有消息角色。
- AC36：恢复会话后，Phase 7 的 Token 估算、工具结果轻量处理、上下文压缩和使用量展示仍然有效。
- AC37：从磁盘恢复的工具交互不会绕过现有权限系统；恢复只重建历史，不会重新执行旧工具，也不会自动批准新的工具调用。
- AC38：项目指令加载失败、会话清理失败或自动记忆失败中的任一项，都不会让另外两个独立能力整体失效。
